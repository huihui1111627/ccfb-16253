# 注册中心自我保护机制模拟

针对"交换机抖动 20 秒 → 心跳全丢 → 注册中心一刀切摘光实例 → 调用方拿到空列表 → 全站故障两分钟"这类事故,用 Go 实现的本地离散事件模拟器,对比**自我保护新模式**与**一刀切旧模式**在五种故障剧本下的表现,并提供可播放的 Web 可视化页面。

## 运行

```bash
go run . list                       # 列出五个剧本
go run . compare                    # 五剧本 × 两模式全量对比
go run . run -mode protected hb_flap   # 单剧本(protected | legacy)
go run . web -addr :8080            # 可视化页面
```

1 tick = 100ms 模拟时间;拓扑为 3 机房 × 2 交换机、12 个服务 × 250 实例 = **3000 实例**、3 节点注册中心集群、6 个调用方。

## 设计如何对应六条需求

### 1. 大批超时 ≠ 实例真挂,先怀疑自己

摘除扫描前先算集群心跳比例。新模式下只要比例已跌破 85% 就先不摘(即时双保险),自我保护标志经 0.5s 连续确认后置位;单个实例真挂时比例几乎不变(1/3000),永远进不了保护,照常 3s 超时摘除。

### 2. 进入/退出条件(`sim/registry.go`)

- **心跳比例**:合并全部节点租约后,`实际(2s 窗口内有心跳) / 期望(集群已知实例,含已摘)`。判定窗口 2s 短于摘除超时 3s,保证保护先于摘除生效。
- **集中度**:丢失实例按机房/交换机聚合,70% 以上集中在同一处视为局部网络故障强信号(机房分区剧本靠它进保护)。
- **迟滞**:进入需连续 0.5s 满足,退出需比例恢复到 90% 并持续 3s,防反复横跳。

### 3. 保护期真挂实例由调用方屏蔽

保护期间注册中心一个不摘,调用方侧两道机制兜底:
- 每实例每 2s 一次**主动健康探测**(槽位打散,有失败苗头的实例加探),连续 3 次失败熔断 1.5s,后半开试探;
- 真实业务调用同样喂熔断器。真挂实例约 2~3s 内不再被调用。

### 4. 集群同步,单节点不连累全局(`Digest` + 租约合并)

实例把注册/心跳 gossip 给全部 3 个节点;节点每 0.5s 交换租约摘要。新模式的摘除判定用**多节点合并视图**(任一节点近期还看到心跳就不摘),本节点直收心跳不足集群一半时自我**降级**、不参与摘除。某节点 90% 丢包时,其余两个节点视图完整,零误摘。

### 5. 调用方缓存防线

- 一个拉取周期内请求全部注册中心,结果取**并集**(任一节点认为实例活着就保留);
- 节点带 `Incomplete` 标记的响应、以及"缓存非空却推来裸空列表",一律拒绝并保留旧缓存;
- 注册中心整体不可达时持续用旧缓存调用,并标记兜底状态。
- 旧模式不设防,空列表直接生效——这正是事故里全站调不通的根因。

### 6. 恢复突发扛压

节点每 tick 最多处理 300 条消息,超出排队(摘要同步走独立优先队列)。网络恢复后 3000 实例同时补注册形成风暴,实测峰值排队约 600 条,约 2s 消化完,不丢注册。

## 五个剧本与对比结果

| 剧本 | 新模式失败 | 旧模式失败 | 新误摘 | 旧误摘 | 新空列表致败 | 旧空列表致败 |
|---|---|---|---|---|---|---|
| 单个实例真挂 | 0 | 0 | 0 | 0 | 0 | 0 |
| 机房网络分区 | 532* | 420* | 0 | 1000 | 0 | 0 |
| 注册中心节点网络差 | 0 | 0 | 0 | 3000 | 0 | 0 |
| 交换机抖动(还原事故) | **0** | 510 | **0** | 3000 | **0** | 510 |
| 真挂与抖动同时发生 | **0** | 510 | **0** | 3000 | **0** | 510 |

\* 机房分区期间分区内实例的数据面本身不可达,任何注册中心策略都无法消除这部分失败;旧模式数字更低是因为它把 1000 个活着的实例误摘了——恢复后这些实例要重新注册才能回到列表,反而拉长了故障尾巴。

关键结论:

- **抖动类事故**:旧模式 20 秒抖动演化为 510 个请求失败、3000 实例全摘;新模式零失败零误摘,保护在抖动开始后 2s 进入、恢复后 3s 退出。
- **真挂实例屏蔽**:新模式靠熔断 2~3s 生效,与旧模式靠摘除的速度相当;两者同时发生时互不干扰。
- **异常空列表**:节点丢包剧本里故障节点推空响应,新模式调用方拒绝并保留完整缓存(页面"拒绝异常空列表"计数可见)。

## 代码结构

```
sim/
  types.go      消息、负载、剧本事件类型
  params.go     全部时间/阈值参数(集中调参)
  network.go    可故障注入的网络模型(机房/交换机/心跳平面/单节点丢包)
  instance.go   服务实例:注册、心跳、恢复补注册
  registry.go   注册中心节点:心跳窗口、租约合并、保护判定、摘除扫描
  caller.go     调用方:并集拉取、空列表拒绝、熔断与主动探测
  engine.go     逻辑时钟、消息投递、故障注入、指标与屏蔽耗时统计
  scenarios.go  五个剧本
  snapshot.go   页面用快照
  *_test.go     10 个单元/场景测试
web/index.html  可视化页面(时间轴播放、机房心跳、保护状态、调用方缓存)
```

## 可视化页面包含

- 各机房实例心跳情况(正常/延迟/超时/宕机四色,可按机房过滤);
- 三个注册中心节点的实时心跳比例、保护/降级状态与**进入保护的原因**;
- 每个调用方手里的缓存实例数、熔断分布、拒绝空列表次数、不可达兜底计数;
- 核心指标(失败请求、误摘、排队峰值)与故障/保护事件时间线,支持播放、单步、拖动。
